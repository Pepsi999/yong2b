## 0. 문서 성격

이 문서는 **사전등록(pre-registration) 문서이자 구현 스펙**이다.
- 아래 가설·파라미터·게이트는 백테스트 실행 **전에** 확정한다.
- 결과를 본 후 파라미터를 소급 수정하면 해당 실험은 기각 처리하고 새 실험 ID를 발급한다.
- REGIME_C 검증 6원칙을 그대로 적용한다:
  1. 임계값은 실데이터에서 도출 (임의 매직넘버 금지)
  2. 사후 서사 금지
  3. 백테스트 없이 효용성 주장 금지
  4. 생존편향 보정 필수
  5. 거래비용 반영 필수
  6. OOS(Out-of-Sample) 검증 필수

## 1. 실험 ID 및 가설

**실험 ID: US-2026-001**

### H1 (레짐 필터)
나스닥100 유니버스에서 시장 폭(breadth) 기반 레짐 필터(% above 200MA)를 적용한 추세추종 포트폴리오는, 레짐 필터 없는 동일 전략 대비 MDD를 유의하게 개선한다 (ΔMDD ≥ +10%p 개선, CAGR 훼손 ≤ 3%p).

### H2 (랭킹 팩터)
12-1 모멘텀(최근 1개월 제외 12개월 수익률) + 52주 신고가 근접도의 복합 랭킹은, 단일 12-1 모멘텀 대비 위험조정수익(Sharpe)을 개선한다.

### H3 (거래량 필터)
20일 평균 거래대금 대비 거래대금 급증(volume surge) 조건을 진입 필터로 추가하면 승률이 개선된다. (보조 가설, H1/H2 통과 후 검증)

### 판정 게이트 (KOSPI 시스템과 동일 철학)
- **G1**: OOS CAGR ≥ 10% AND OOS MDD ≥ −40%
- **G2**: IS 대비 OOS Sharpe 열화 ≤ 40%
- **G3**: 벤치마크(QQQ Buy&Hold) 대비 OOS 위험조정수익 우위 (Sharpe 기준)
- G1과 G3 중 하나라도 미통과 시 해당 변형 기각

## 2. 유니버스

- **대상**: NASDAQ-100 구성종목
- **생존편향 보정 필수**: 현재 구성종목만으로 백테스트 금지.
  - 방법 A(권장): Wikipedia "Nasdaq-100 changes" 히스토리를 파싱하여 시점별 구성종목 테이블 구축
  - 방법 B(대안): 편입/편출 이력 CSV를 수동 구축 (2010년 이후만이라도)
  - 시점별 구성 불가능한 구간은 백테스트 기간에서 제외하고 문서에 명기
- 유니버스 테이블 스키마 예시:
  ```
  nasdaq100_history(date DATE, ticker VARCHAR(10), in_index TINYINT)
  ```

## 3. 데이터

### 3.1 가격 데이터
- **소스**: yfinance (연구 단계 무료), 일봉 OHLCV + 수정주가(auto_adjust=True)
- **기간**: 2005-01-01 ~ 현재 (가능한 최장)
- **저장**: 로컬 SQLite 또는 CSV/Parquet (MariaDB 연동은 v1에서. v0는 독립 실행 가능해야 함)
- 상장폐지 종목은 yfinance에서 데이터가 없을 수 있음 → 결측 종목 리스트를 별도 로그로 남기고 유니버스 커버리지 비율을 리포트에 명기 (커버리지 < 85%면 결과 신뢰도 경고 표시)

### 3.2 시장 폭(breadth) 데이터
- 외부 소스 쓰지 말고 **유니버스 가격에서 직접 계산**:
  - `pct_above_200ma`: 유니버스 내 200일 이평 상회 종목 비율
  - `pct_above_50ma`: 50일 이평 상회 비율 (보조)
- 벤치마크 지수: QQQ (수정주가)

### 3.3 환율
- v0에서는 USD 기준으로만 성과 계산. KRW 환산 성과는 참고치로 USDKRW(yfinance `KRW=X`) 적용해 별도 표기.

## 4. 전략 규격 (v0 확정 파라미터)

### 4.1 레짐 판정 (월말 기준)
| 레짐 | 조건 | 액션 |
|---|---|---|
| BULL | pct_above_200ma ≥ 0.60 | 주식 100% (TOP-N 보유) |
| NEUTRAL | 0.40 ≤ pct_above_200ma < 0.60 | 주식 50% + 현금 50% |
| BEAR | pct_above_200ma < 0.40 | 전량 현금 (v0에서는 현금, 국채 ETF 치환은 v1 실험) |

- 임계값 0.60/0.40은 **초기 가설값**이며, IS 구간에서 grid search(0.30~0.70, step 0.05) 후 확정. 확정 근거를 리포트에 명기 (원칙 1).
- 판정 빈도: 월말 종가 기준, 익월 첫 거래일 시가 집행 (실행 타이밍 바이어스 방지 — F-02 교훈 적용)

### 4.2 종목 랭킹 (H2)
- `mom_12_1`: (P[t-21] / P[t-252]) − 1
- `dist_52w_high`: P[t] / max(P[t-252:t]) — 1에 가까울수록 신고가 근접
- 복합 점수: `score = 0.5 * rank(mom_12_1) + 0.5 * rank(dist_52w_high)` (cross-sectional 백분위 랭크)
- 비교군: `score = rank(mom_12_1)` 단독

### 4.3 포트폴리오 구성
- TOP-N = 10 종목, 동일가중
- 리밸런싱: 월 1회
- 최소 유동성 필터: 20일 평균 거래대금 ≥ $50M (진입 시점 기준)

### 4.4 거래비용
- 편도 **0.10%** (미국 시장: 커미션 무료 시대이나 슬리피지+스프레드 보수적 반영)
- 월 리밸런싱 회전율 기준 왕복 반영

### 4.5 IS / OOS 분리
- IS: 2005-01-01 ~ 2018-12-31 (파라미터 탐색 허용)
- OOS: 2019-01-01 ~ 현재 (파라미터 고정, 1회만 실행)
- OOS를 여러 번 돌려보고 고르는 행위 금지 (원칙 2, 6)

## 5. Claude Code 구현 단계 (체크포인트 방식)

각 단계 완료 시 산출물을 확인한 후 다음 단계 진행. 한 번에 전부 구현하지 말 것.

### CP-1: 유니버스 구축
- `build_universe.py`: 나스닥100 히스토리 파싱 → `nasdaq100_history` 테이블/parquet 생성
- 산출물: 시점별 구성종목 수 검증 리포트 (매 시점 95~105 종목 범위인지 체크)

### CP-2: 가격 데이터 수집
- `fetch_prices.py`: yfinance로 유니버스 전 종목 + QQQ + KRW=X 일봉 수집, parquet 저장
- 산출물: 커버리지 리포트 (종목별 시작일/결측일 수/상폐 종목 목록)

### CP-3: 팩터 및 breadth 계산
- `compute_factors.py`: mom_12_1, dist_52w_high, 거래대금, pct_above_200ma/50ma 계산
- 산출물: breadth 시계열 차트 (영문 chart.png + 한글 chart_ko.png, 파일 헤더에 작성일 KST 명기)

### CP-4: 백테스트 엔진
- `backtest.py`: 월말 시그널 → 익월 첫 거래일 시가 집행, 비용 반영, 레짐별 포지션
- 룩어헤드 체크리스트 내장 (v9.39 cross_rank 버그 교훈):
  - [ ] 랭킹 계산에 당일 종가 이후 정보 미사용
  - [ ] breadth 계산 시점 = 시그널 시점
  - [ ] 유니버스 구성은 시그널 시점 기준 (미래 편입 종목 사용 금지)
- 산출물: IS 구간 결과 (CAGR, MDD, Sharpe, 회전율, 연도별 수익률)

### CP-5: IS 파라미터 확정
- 레짐 임계값 grid search (IS만), TOP-N {5, 10, 20} 민감도 테이블
- 산출물: 파라미터 확정 문서 + 민감도 표. **여기서 파라미터 동결 선언**

### CP-6: OOS 1회 실행 및 게이트 판정
- 산출물: OOS 결과, G1/G2/G3 판정표, QQQ B&H 대비 비교 차트(영/한 2장)
- 통과 시 → v1 로드맵(H3 거래량 필터, BEAR 국채 치환, KRW 환산 리스크) 논의
- 미통과 시 → 기각 문서화 후 종료 (파라미터 재탐색으로 되돌아가려면 새 실험 ID 발급)
